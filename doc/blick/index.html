Crate blick 

Source
Expand description

Serves Blick and runs Flux on programs pasted into it.

cargo run -p blick [-- --port 8765] [DIR]

Then open http://127.0.0.1:8765. On startup, blick installs the client’s npm packages when they are missing or out of date (npm ci), and starts vite build --watch on the client, which rebuilds client/dist whenever a source file changes. The page reloads after each rebuild. It needs Node.js and npm.

  • GET /api/info: {command, repo, dir}, shown in the page’s status line.
  • GET /api/files: {root, files}, the .rs files under DIR (relative paths), which the page lets the user open; 404 when blick was started without one.
  • GET /api/file/<relative path>: the contents of one of them.
  • GET /api/run-ws (WebSocket): the page sends {source, flags}; the server streams every output line as {"type": "line", "text": ...} while cargo x run works, then sends {"type": "done", ...result} and closes. See run.rs.
  • GET /api/reload (WebSocket): the server sends reload after the client was rebuilt.
  • Everything else is a file of client/dist.

The server compiles whatever it is sent, so it only listens on localhost.

Modules§

files 🔒
The folder of programs the page can open (blick <dir>), e.g. Flux’s regression tests.
protocol 🔒
The messages between the server and the page. Their TypeScript types are generated from these definitions (see write_bindings) into client/src/bindings.
run 🔒
Running Flux on a program: cargo x run <file> -- -Fdump-checker-trace=debug from the repository root, so Flux and its sysroot are rebuilt when needed, exactly as on the command line. Its output is streamed as it is printed; Flux writes the trace to a file, and rustc the MIR of each body (-Zdump-mir=renumber: the body borrow checking, and so Flux, works on) to a directory.
