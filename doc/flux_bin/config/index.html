Loading of .flux/config.toml, the configuration of a cargo flux invocation.

Configuration files are discovered and merged following the same rules cargo uses for .cargo/config.toml:

  • Starting from the current directory, .flux/config.toml is read in every ancestor directory, followed by $FLUX_HOME/config.toml (~/.flux/config.toml by default) if it wasn’t already found.
  • Files closer to the current directory take precedence. Tables are merged key by key, arrays are concatenated (with items from higher precedence files placed later), and any other value is replaced.
  • Relative paths are resolved relative to the parent of the directory containing the file, e.g., a path in /project/.flux/config.toml is relative to /project.

Settings can be overridden for specific packages in [package.<spec>] tables, where <spec> is a package name, <name>@<version>, or * for all packages that are not workspace members. As in cargo’s profile overrides, a package’s settings are taken from its own table, then from [package."*"], and then from the top level.
